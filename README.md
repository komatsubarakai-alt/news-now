# ニュースの現在地 v1.0

札幌のニュースを出来事ごとに整理し、現在地と報道の時系列を表示します。
追跡対象は「事件・事故」「災害」「政策・制度」「企業・組織」「地域・インフラ」の5カテゴリーです。

## v1.0の完成範囲

1. **過去さかのぼり**：新規イベントと既存イベントの初回移行時に固有検索語を作り、Google News RSSで保存記事より古い報道を検索。同一案件と高確度で確認できた検索結果だけ追加します。過去記事を追加しても現在地・進展回数は戻しません。
2. **完結・休眠・保管**：明示的な終結報道を確認すると `completed`。重要な進展が180日ない場合は `dormant`。今後の予定がある案件は休眠対象から外します。全状態を `events.json` に削除せず保存し、追跡中／休眠中／完結・保管の表示を切り替えます。新たな重要な進展があれば追跡を再開します。
3. **進展判定**：関連記事の追加と、逮捕→起訴などの重要な進展を区別します。同内容の再報道は記事のみ追加。進展時だけ現在地・最終進展日・進展回数・根拠付き履歴を更新します。移行前の更新は進展回数に数えません。
4. **将来予定の追跡**：タイトルに明示された予定と根拠を保存。明示された年月日は日、年月は月、年だけなら年の範囲を保持。年が不明、「来春」、年度などは日付未確定のまま保存し、推測で日付を作りません。確定した予定範囲の7日前から、期限後14日まで1日1回、それ以後は週1回の追加検索。時期が過ぎても実施済みにしません。

関連イベントのリンク・情報訂正管理・通知・課金・公開範囲の変更は今回の範囲外です。

## 実行

```sh
python -m unittest discover -s tests -v
# 先行処理でnews_status.jsonを作成してから実行
OPENAI_API_KEY=... python event_tracker.py
```

毎時17分の既存Actionsで収集・更新します。時刻通りの実行はGitHub側の混雑で遅れる場合があります。
AIモデルは既存設定の `gpt-5.4-mini`、追跡エンジンのみ `TRACKING_MODEL` で変更できます。

## 保護と上限

- 追跡エンジンのAI呼び出しは1実行30回まで。新着判定は16グループまで、既存メタデータ移行と過去検索は各2イベント、予定検索は3イベントまで。先行する分類・現在地生成のAI呼び出しは別です。実際のAPI費用は利用量に依存します。
- 判定失敗や不確実な新着は `tracking_pending.json` に保存し、次回に再判定。RSSから消えても判定待ちデータは残します。
- 過去検索は成功した初回のみ。通信等の失敗は3回まで再試行し、失敗継続時は `needs_review` にします。再試行には該当イベントの `backfill` をリセットします。
- `tracking_health.json` に最終実行・判定保留数・追跡AI呼び出し数・過去検索要確認数を記録。
- イベントの保存は一時ファイルからの置換。既存ID・記事は維持し、アーカイブも同じデータで保存します。
- 記事本文は保存せず、タイトル・公開日時・URLから整理します。検索サービスに残っていない過去記事の完全復元や、AI判定の完全な正確性は保証できません。曖昧な終結・予定は断定せず確認待ちにします。
- Web表示はテキストとして生成し、リンクはHTTP/HTTPSのみ許可します。

## 検証

テストはAPI・検索をモックし、進展、重複、過去記事、完結、休眠と再開、予定の精度、期限検索、判定失敗の保存を検証します。
既存16イベントの予定抽出・過去検索は定期実行で順次処理します。
実運用のAI照合精度は、v1.0反映後に1〜2週間の自動運転で確認します。

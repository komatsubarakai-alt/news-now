# スマホ運営者管理画面：隔離試作の使い方

この画面は端末内の一時SQLiteだけを操作します。本番サイト・本番承認・実AIには接続しません。PR #17はDraftのままです。GitHub Pagesなどへ配置しないでください。リポジトリにはソースと検証記録だけを追加し、生成した管理HTML、内部DB、確認記録を公開しません。

## 起動して操作する

Python 3.12で検証しました。管理アプリ自体はPythonの標準ライブラリだけで動きます。まずPR #17のブランチを端末のローカルに用意します。

リポジトリのフォルダーで次を実行します。

```sh
python experiments/engine_v2/operator_app.py --demo
```

表示された `http://127.0.0.1:8765` を **同じ端末の** Chromeで開きます。架空の事件・記事・保存済み模擬回答が入り、既存の検証を通した判断が1件だけ用意されます。初期状態では承認0件、公開可能0件です。実ニュースの証拠ではありません。

Androidで操作するには、スマホ内でPythonを動かせる環境（例：Termux）が別途必要です。PCで起動した127.0.0.1を、スマホのChromeから開くことはできません。端末間公開・トンネル・クラウド公開は用意していません。Android実機・Termuxでの起動は未確認です。Chromeのスマホ相当画面による検証結果と区別してください。

### 操作の順序

1. 一覧の確認待ち記事を開き、日時・媒体・URL・全候補と順位を確認します。最初は20組だけ表示し、必要に応じて追加表示します。件数は保存済みの段階別記録数で、同じ記事の重複や過去の判定記録を含みます。すべてが新たな手動判断を必要とするという意味ではありません。保存時の状態も表示します。
2. 候補を選び「同一事件」「別事件」「保留」を記録します。保留理由は定型ボタンでも入力できます。原文一致の根拠が不足すると、同一・別事件の記録は停止します。候補なしでも保留できます。
3. 「記事・根拠を確認」で事件の詳細を開きます。本文未取得、引用未提供、古い記事版を区別して表示します。媒体情報がなければ未確認と表示します。
4. 判断の記録は確認記録です。記事の採用、事件の統合、正解ラベルへの昇格、公開承認は自動実行しません。安全検証済みの採用判断がなければ公開承認は停止します。
5. 公開対象を項目ごとに確認します。事件・記事・現在地の各項目・進展・予定・訂正・記事改訂は別の承認です。「承認前・仮承認後を比較」は検証エンジンを一時実行し、必ず取り消してから表示するため、承認を保存しません。
6. 「公開承認」で対象内容・判断ID・根拠IDを確認し、理由を入れ、「確認して実行」を押します。引用元すべての記事と事件を承認するまで、公開プレビューに事件が出ない場合があります。架空デモでは記事2件と事件を個別に承認します。
7. 「公開プレビュー」は既存の公開承認エンジンが返した承認済みJSONです。未承認の比較用JSONは読みません。取消し・再承認も理由と確認操作が必要です。
8. 操作履歴で判断ID・記事版・承認状態・取消し履歴を確認します。確認記録はJSON保存できます。このJSONは本番の権限証明や正解データではなく、自動取り込み機能もありません。

記事URLは自動では開きません。リンクを押すと外部記事を開く確認が出ます。今回の検証では押していません。

### 保存・再起動

操作はSQLiteトランザクションで保存します。画面を再読込しても失われません。下書き理由はブラウザー内、送信未完了コマンドはセッション内に保存します。送信結果が不明なら「未完了操作を同じIDで再送」で確認できます。同じ操作IDに別の内容は使用できません。

終了は起動端末でCtrl+C。再開は、起動時に表示されたSQLiteのパスを指定します。

```sh
python experiments/engine_v2/operator_app.py --db /tmp/news-now-operator-EXAMPLE/operator.sqlite
```

パスは実際に表示された値に置き換えます。Androidでは一時フォルダーの場所が異なります。`/tmp` 固定ではなく、Pythonが認識する一時フォルダーを使用します。OSによる一時フォルダーの削除を越えた保存保証・自動バックアップは未実装です。ブラウザーの記憶域を消すと下書きや未完了コマンドは失われますが、SQLiteに保存済みの記録は残ります。

## 保存済みデータを読む

```sh
python experiments/engine_v2/operator_app.py --snapshot /path/to/read-only-snapshot
```

元JSONは読み取りのみ。一時DBへコピーします。保存済みAIの採用結果や既存公開34件を、自動承認にはしません。再検証済みの採用判断・原文一致の引用がない場合、承認できない状態が正常です。元JSONにない本文・引用・確認日時は作りません。

前段試作品の一時SQLiteを引き継ぐ場合は、新しい別ファイルへ読み取り専用バックアップを作ります。

```sh
python experiments/engine_v2/operator_app.py --copy-db /tmp/previous-rehearsal.sqlite --db /tmp/new-operator.sqlite
```

コピー元は一時フォルダー内の判断同期試作DBに限定します。既存のコピー先は上書きしません。元DBの判断・承認・記事版・履歴を保持します。直接起動できるのは管理試作用マーカーのある一時DBだけで、本番DBを指定できません。

## スマホへ持ち運べる閲覧専用HTML

```sh
python experiments/engine_v2/operator_preview.py --demo --output /tmp/news-now-operator-preview.html
```

生成ファイルをスマホへ移して開くと、画面・根拠・承認状態をオフラインで確認できます。**単独HTMLでは判断の保存・仮承認・承認・取消しはできません。** これらは同じ端末のローカルサーバーで行います。Android Chromeでのファイルの開き方やファイル権限は実機未確認です。

`--demo` の代わりに `--snapshot /path/to/read-only-snapshot` を指定すれば、保存済みデータの閲覧版を生成します。内部情報を含むため、生成HTMLをインターネットへアップロードしないでください。確認記録も扱いは同じです。

## 安全の境界

- サーバーは127.0.0.1だけ。外向きアドレスで起動する設定はありません。任意ファイル配信・DB書換え・AI呼出し・ニュース取得のAPIはありません。
- Host、Origin、起動ごとのトークン、入力サイズ、内容ハッシュと画面世代を検査します。外部サイトからの操作を拒否します。
- 承認ボタンの可否表示だけを信用せず、保存時にも既存publication.approve / withdrawを実行します。記事改訂後の古い画面・古い判断・無効な引用は再確認になります。
- 本人認証、実権限管理、端末内の悪意あるアプリへの対策、DB暗号化は未実装です。端末内トークンは本番認証の代わりではありません。
- 正解未確認の判断を確定しません。本文確認・引用追加・模擬AIによる新規再判定を画面から開始する操作は未実装です。
- 本番公開・本番反映・mainマージ・インターネット公開は今回の対象外です。

## 検証を再現する

```sh
python experiments/engine_v2/operator_validate.py
```

リポジトリ全体を一時コピーし、実通信を遮断して現行208件＋試作265件を実行します。元コピー・実行コピーの本番JSONのハッシュを比較します。UIの実ブラウザー検証は別工程で、PlaywrightとChromiumがあらかじめある環境を使用します。

```sh
python experiments/engine_v2/operator_browser_check.py --output-dir /tmp/news-now-operator-browser-results
```

ブラウザーのアクセス先を127.0.0.1だけに制限し、外部の要求は遮断・記録します。実機Androidの検証ではありません。この環境ではfile:によるHTML直接表示がブラウザーポリシーで禁止されているため、生成HTMLをページ内容として読み込んだ検証と、実際のファイル開封は区別しています。

# 今日の確認作業：スマホ向けの使い方

この画面はPR #17の隔離試作です。本番サイトや本番データには反映しません。Python 3.12と標準ライブラリでローカルサーバーを動かします。Chromeから記事を自動取得したり、AIへ送信したりしません。

## 日常の3つの確認

最初の「今日の確認作業」には次の4つの入口があります。

- **事件の判定待ち**：追跡中の事件と、新しい記事が同じ事件かを確認します。
- **続報・進展の確認待ち**：同じ事件かは記録済みで、進展の確認がまだの作業です。
- **公開の確認待ち**：安全検証済みの採用判断がある事件について、読者に出す内容を確認します。
- **保留・再確認が必要**：根拠不足、訂正の疑い、運営者の保留、記事改訂などを先に見ます。

同じURLの同じ版は段階間でまとめ、元の待機先は「詳細情報」にすべて残します。版が複数あって現在版を確認できない場合は、1件の照合保留として各版を表示します。共有記事で既に別々の事件への対応が分かっている場合は、事件ごとの作業を残します。公開確認は、内部の項目数ではなく事件ごとの1件です。

過去の判定記録、内容不変で採用済みの記事、自動処理待ちを、人に必要な作業へ足しません。再試行の予算待ちも人の判定件数にはしません。未知の状態を「確認済み」と推測するのではなく、自動処理待ちに分けます。明示的な手動確認・根拠不足・運営者保留と、改訂・訂正リスクを確認対象にします。

### 記事を1件確認する

1. 作業の種類をタップし「確認する」を押します。優先理由が表示されます。20件ずつページを切り替えられます。
2. 事件名・現在の進展段階・重要な経過を読みます。新しい記事の見出し・媒体・日本時間の公開日時と比較します。
3. 引用と注意点を確認します。「本文未確認」「見出し一致・原文未確認」は本文を確認した意味ではありません。「保存本文との文字列一致」でも、出典の正しさが確認済みという意味ではありません。
4. 第1段階で「同じ事件」「別の事件」「判断できない・保留」を選びます。引用がない場合は保留できます。
5. 同じ事件を選んだ場合だけ、第2段階で「新しい進展あり」「新しい進展なし」「不明」「訂正・撤回の可能性」を選びます。進展ありの場合は、記事に書かれた段階を引用で確認して選びます。
6. 理由を入力して記録します。「事件の確認だけ記録」を使うと、進展の確認待ちへ移ります。保存後は同じ種類の次の作業へ進みます。

**確認記録を保存しても、事件の統合・新規登録・進展の確定・公開は自動実行しません。** 既存の採用検証は別の工程です。公開日時を出来事の発生日時へ転記しません。未提供の発生日時は未確認です。

「新しい進展あり」と入力されても、選んだ段階の引用がなければ根拠不足として保留します。記録済みの同段階の引用を新しい引用がそのまま含む場合は、重複報道の候補として別記します。いずれも進展回数を増やしません。文字列一致だけで同じ事実と確定した意味でもありません。

訂正・撤回の選択は、通常の進展とは別の確認記録・訂正アラートへ保存します。見出しに「訂正」「撤回」などがある場合は優先表示し、通常の進展として入力しても訂正の疑いとして保留します。この簡単な語の検出は誤報の確定ではなく、本文全体の自動判定でもありません。

### 確認済み・保留・再確認

画面下の「今日の作業へ」で戻れます。「確認済み・履歴」は未処理とは別の画面です。確認済みでも、まだ安全検証待ちであり正解データではありません。「この判断を見直す」で理由を入力すると、古い記録を残して保留へ戻せます。

運営者の保留は自動キューの状態が変わっても消しません。本文・見出し・選んだ事件の内容が変わると再確認になります。無関係な別事件の変更や、同じ内容の単なる再観測では確認済み作業を増やしません。古い本文に戻っても、以前の確認・承認は自動復活しません。

### 公開前に確認する

公開の確認画面では、読者向けの事件名・概要・現在地・進展の時系列・根拠記事・訂正をまとめて表示します。これは**未承認の内部確認用**で、そのまま公開できるデータではありません。

1. 今回確認する項目をチェックします。「安全検証を通せる未承認項目を選択」も使えます。停止中の項目は選べません。
2. 「選んだ内容の公開前プレビュー」で、既存の公開承認エンジンを仮に通した結果を見ます。この段階の承認は保存しません。
3. 「まとめて最終確認」で、各対象・内容・根拠・判断を確認し、理由を入れて実行します。内部では1項目ずつ既存の承認検証を実行します。1つでも失敗すれば、今回の操作はすべて保存せず停止します。
4. 保存後の公開内容を確認します。事件と、根拠に使うすべての記事の承認が揃わないと、出力に事件が出ない場合があります。結果と各項目の承認IDは詳細情報に残します。

公開取消しも理由と確認が必要です。記事や根拠が変わると影響する承認は失効し、再判定・明示的な再承認が必要です。未承認項目や根拠の足りない項目を、見かけの一括操作で承認しません。

## 起動と保存

リポジトリのPR #17ブランチで次を実行します。

```sh
python experiments/engine_v2/operator_app.py --demo
```

表示された127.0.0.1のURLを**同じ端末**のChromeで開きます。架空の10ケースと操作練習用の事件が入ります。初期承認は0件です。PCで起動した127.0.0.1へ別のスマホから接続することはできません。Android上で操作を保存する場合は、端末内のPython環境（例：Termux）が必要です。その実機での起動は未確認です。

起動時に表示されたSQLiteのパスを控え、再起動時は `--db 実際のパス` を指定します。ブラウザーを再読込しても保存済み記録は残ります。理由の下書きはブラウザー内、送信前の操作はセッション内、保存済み判断・承認・履歴は一時SQLiteに保存します。「未完了の操作を同じ番号で確認」は同じ操作IDを再送し、二重保存を防ぎます。

一時フォルダーをOSが削除した場合の復旧保証、自動バックアップ、端末間同期はありません。

保存済みJSONは次で読み取り専用のコピーとして読み込みます。

```sh
python experiments/engine_v2/operator_app.py --snapshot /path/to/read-only-snapshot
```

既存の試作DBは、元を読み取り専用で開いて新しい一時DBへコピーできます。コピー先を上書きしません。

```sh
python experiments/engine_v2/operator_app.py --copy-db /tmp/previous.sqlite --db /tmp/new-operator.sqlite
```

## Pythonなしで確認する閲覧専用HTML

Codex側で次の生成を行います。利用者がPythonを実行する必要はありません。

```sh
python experiments/engine_v2/operator_preview.py --demo --output /tmp/news-now-operator-simple-preview.html
```

受け取ったHTMLを端末に保存してChromeで開きます。選択して表示を試せますが、判断・承認・取消しは保存できません。架空データと未再検証の保存データは画面上で区別します。元HTMLは外部のライブラリ・サーバー・通信を必要としません。

添付できない環境では、元HTMLの全文を番号順に分割してチャットで受け渡せます。より短い受け渡し用HTMLも作れます。

```sh
python experiments/engine_v2/operator_handoff.py --html /tmp/news-now-operator-simple-preview.html --output-dir /tmp/operator-handoff
```

`save-preview.html` と、その全文を短く分割した `save-preview-part-01.txt` 以降が生成されます。断片の中身を番号順につなぎ、UTF-8のsave-preview.htmlとして保存します。説明文・コードブロック記号は入れません。各断片末尾の改行を1つ保持します。

そのHTMLをChromeで開いて「閲覧用HTMLを保存」を押すと、端末内で元HTMLを復元し、SHA-256が一致した場合だけ保存します。インターネットには送信しません。復元にはChromeのDecompressionStreamとWeb Cryptoが必要です。未対応なら安全停止します。Chrome相当ブラウザーで元HTMLとバイト一致することを検証しますが、Androidのファイル開封・ダウンロード動作は実機未確認です。

生成したHTML・内部DB・確認記録はGitHubへコミットせず、GitHub Pagesなどへ公開しません。

## 安全と未実装

- 既存の根拠・矛盾・保存前検証、記事版、運営者判断、公開承認・失効・取消しの検証は維持します。
- AI候補の絞り込み、進展・重複・訂正の自動判定は将来の接続対象です。今回は保存済み結果・架空データ・模擬回答だけで、実AIは呼び出しません。
- 人の確認記録を正解ラベルや公開承認へ昇格しません。本文・引用・日時の捏造も行いません。
- 本人認証・本番の権限管理・暗号化・永続DB・バックアップ・複数端末同期は未実装です。Host・Origin・端末内トークンは本番認証の代わりではありません。
- データ取得はまだ全件です。20件表示はUI側のページ分けで、サーバー側の分割取得・検索・順位キャッシュは未実装です。
- UIからの本文追加・引用追加・実AIによる再判定開始は未実装です。足りない根拠を画面の操作だけで補った扱いにはしません。
- 本番導入・本番公開・mainマージは今回行いません。

## テストの再現

```sh
python experiments/engine_v2/operator_validate.py
python experiments/engine_v2/operator_browser_check.py --output-dir /tmp/operator-browser-results
```

最初のコマンドは一時コピー・通信遮断で現行208件＋試作313件を検証します。ブラウザー検証には、あらかじめPlaywrightとChromiumがある環境が必要です。360/393/412pxのChrome相当表示を使い、実機Androidの検証とは区別します。

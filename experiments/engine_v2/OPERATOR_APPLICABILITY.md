# 運営者判断の差分確認（隔離・閲覧専用）

元の判断と、現在への適用評価を分離します。判断を変更・移行・再承認する
機能や本番接続はありません。有効候補は、記録を参照できる候補という意味で、
根拠の成立・公開承認・自動適用を意味しません。

## ファイル

- `operator_applicability.py`：純粋な差分・評価、別SQLiteへの評価保存、静的HTML生成
- `operator_applicability_demo.py`：架空の入力生成（実ニュース・個人情報なし）
- `operator-applicability-demo.html`：単独で開ける架空サンプル
- `test_operator_applicability.py`：架空データの回帰検証

## 画面の使い方

事件一覧から対象を開き、追加・改訂・削除・移動の表示を確認します。
判断時と現在の記事一覧、各判断の保存理由・元記事版・評価理由を折りたたみで確認できます。
承認・保存・反映ボタンはありません。JavaScript、外部CSS、画像、外部通信は不要です。
URLは文字列表示のみで、誤った外部アクセスを避けます。

```sh
python experiments/engine_v2/operator_applicability.py --demo --output /tmp/judgment-demo.html
```

実データは、公開リポジトリ外の非公開入力 `{"items":[...]}` から生成します。

```sh
python experiments/engine_v2/operator_applicability.py --input /private/input.json --output /private/review.html
```

実ニュースを含む入力・HTML・SQLite・画面写真をGitへ追加しないでください。
この生成コマンドはリポジトリ内へのHTML出力を拒否します。
PRのHTMLは架空入力を別フォルダーで生成してから複製したものです。

## 入力・評価

各items要素：

- `decision`：元記録全文。ID・対象ハッシュ・記事指紋・全文グループハッシュ・理由を照合
- `original_target`：元の対象ハッシュを再現する保存時事件。推測で復元しない
- `current_target`：比較する現在事件
- `source_group`：元の判断が参照する記事グループ。代表URLへ差し替えない
- `constraints`：呼び出し側が照合した範囲の `checked`, `basis` と、既知の `conflict`,
  `known_distinct`, `split_into`, `merged_into`。未照合ならunknown
- `dependencies`：保存済み依存関係がある場合のみ。`state` はcurrent/changed/expired/
  cancelled/needs_recheck等。欠落時はNoneとして未検証警告を維持
- `article_event_bindings`：保存された現在のURL→事件ID対応。共有は統合の根拠としない

|状態|意味|
|---|---|
|有効候補|元対象・元記事版・保存理由・照合した制約が対応する参照候補。自動適用は常に禁止|
|再確認待ち|記事追加、改訂、削除、記事順序、元記事グループや依存根拠、概要等が変更|
|無効候補|分割・統合・移動・別事件制約・判断競合・対象利用停止|
|判定不能|保存時状態、理由、ID整合性、制約の照合範囲や依存記録が不足・不明|

元のハッシュ方式（事件ID・名称・分類・公開状態・記事配列）と互換にし、
概要・進展段階の変更は別途確認します。元の方式にない項目を過去へ追記しません。
記事の並び順だけでもハッシュが変わり得ることを表示します。
URL一致だけで版を同一扱いせず、本文を含む保存記事の変更を比較します。
表示する派生版ハッシュは過去に保存された版IDではありません。
保存理由を引用へ変換せず、本文・出典確認は未確認のまま表示します。

引用・本文版依存が未記録でも、変更なしの記録は参照候補にはできますが、
根拠の成立は未確認です。記事追加があれば影響なしとは確定せず再確認待ちになります。
外部サイトの削除や、保存データに残っていない改訂は検知できません。
別事件制約・分割統合の存在は入力で証明される範囲だけを扱います。
この機能を本番の採用・公開ゲートとして使わないでください。

## 評価記録の保存と復元

画面は保存しません。隔離テスト・将来の確認履歴用途にのみ、Python APIの
`open_store`, `record`, `restore_originals` を用意しています。

- 本番とは別の、リポジトリ外の新規SQLiteだけを使用
- original_decisions / applicability_assessments / applicability_runs を分離
- 元記録・評価はUPDATE/DELETEをトリガーで拒否
- ルール実装ハッシュ・入力ハッシュ・操作ID・記録日時を保存
- 同一操作の再実行は保存済み結果を返し、変更した入力での操作ID再利用を拒否
- 同じ判断IDに異なる元記録を上書きしない
- SQLiteトランザクションで評価・元記録・操作を同時保存。途中障害は全体ロールバック
- `restore_originals` は元記録を返すだけ。本番への書き戻し機能はない

## 検証と残る条件

`run_offline.py` で既存テストと新しい回帰テストを一時コピー上で実行します。
ネットワークを遮断し、JSONの前後ハッシュを照合します。
記事の追加・訂正・削除・移動・分割統合・競合、複数判断、代表化解除、
元データ不変、二重処理防止、保存障害と再起動を確認します。

本番接続には、正式な記事版・引用依存記録、全制約の継続照合、認証・権限、
私的資料の安全なスマホ配布、監査・バックアップ・復旧方針が必要です。
本機能はそれらを有効化せず、既存の根拠・公開承認ゲートも変更しません。

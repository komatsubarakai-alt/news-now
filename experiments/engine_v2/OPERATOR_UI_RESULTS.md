# スマホ運営者管理画面：隔離試作の結果

操作するローカル画面と、持ち運べる閲覧専用HTMLの生成器を追加しました。既存エンジンの判断同期・引用検証・公開承認・取消しを呼び出します。既存の安全検証・予算制限・本番経路は変更していません。

## 実装範囲

|画面・機能|実装・制限|
|---|---|
|一覧|保存済み待機・判定記録、事件、承認待ち項目、再確認判断を表示。待機記録は20組ずつ表示。段階間の同記事を勝手に削除しない|
|詳細|見出し、公開日時、媒体、不明の明示、URL、全事件候補と順位、記事版、原文引用と一致状態。外部記事は自動取得しない|
|判断|同一事件・別事件・保留、定型理由、自由入力、確認記録のJSON出力。原文引用不足では同一・別事件を停止。保留は保持|
|承認|事件、記事、現在地などの表示項目、進展、予定、訂正、記事改訂を個別に管理。既存のpublication.approveを保存時にも必ず実行|
|取消し・再承認|対象・根拠ID・判断IDを確認し、理由を入れて実行。取消し履歴を保持し、以前の承認は自動復活しない|
|履歴|記事改訂、運営者判断原記録、判断IDと状態、承認・取消しの履歴を表示|
|公開前後|項目の仮承認をSQLiteのSAVEPOINT内で実行し必ずロールバック。実承認後と同じ公開エンジンで比較。公開プレビューは承認済み出力のみ|
|改訂への対応|記事変更後に関係する判断・承認を再確認表示。古い画面からの保存を拒否|
|再実行|操作ID＋コマンドハッシュ＋SQLite一括保存。送信前にコマンドをセッション記憶域へ保存し、不明時は同じIDで再送|
|保存|判断・承認は一時SQLiteへ、理由下書きはブラウザーへ保存。SQLite再起動を検証|
|単独HTML|ネットワーク不要の閲覧専用版を生成。判断の保存・承認はローカルサーバーが必要|

操作手順と起動コマンドは **OPERATOR_UI_GUIDE.md**。標準ライブラリのローカルサーバーは127.0.0.1だけで待ち受けます。実際に動く画面・内部DB・生成HTMLをインターネットへ配置していません。

## 検証結果

- **473テスト成功、失敗0、例外0、実通信試行0**。前段436件に、管理操作31件と閲覧HTML6件を追加。
- 保存前障害では承認・履歴・操作受付をすべてロールバック。保存後の応答消失は同じ操作IDで回復し、二重承認しない。
- SQLiteを閉じて再度開いても、状態と操作受付が一致。同じ操作IDで別の内容は拒否。
- 根拠不足の直接送信、未確認の採用判断、確認操作なし、古い画面、記事範囲の改変、既存DB上書き、リポジトリ内DB、シンボリックリンクを拒否。
- 運営者の保留で既存承認が再確認になり、同一事件へ判断を置き換えても、自動再承認しない。
- 予定・訂正の対象を個別表示し、検証済み採用判断にない内容は承認停止。

**Chromiumのスマホ相当表示で21項目を検証**。393pxで一覧・詳細、360/412pxで履歴の横はみ出しなし。48px以上のボタン・入力、判断・保留、確認の取りやめ、二重クリック、仮承認と実承認の出力一致、公開取消しと再承認、JSON出力、再読込後の下書き、見出し訂正後の再確認表示を確認しました。外部ページ要求0、ページ内JavaScriptエラー0。異なるHost・Origin・誤ったローカルトークンの操作も拒否しました。

これは **Android実機の確認ではありません**。また、この環境はfile:への直接遷移を管理ポリシーで禁止しているため、単独HTMLは内容をブラウザーに読み込んで検証しました。Android Chromeのファイル開封、Termuxでの起動、ソフトキーボードやOSによる停止からの復帰は未確認です。

## 残る安全上の問題・未実装

1. 本番の本人認証・権限管理・DB暗号化・端末喪失対策がない。端末内トークンは本番認証ではない。
2. UIから本文の確認結果や新しい引用を取り込み、安全に再判定する一連の入力画面は未実装。既存の判断同期の経路は維持しているが、画面からは呼び出さない。
3. 一時SQLite以外の永続化・バックアップ・OS削除後の復旧・複数端末同期は未実装。
4. 実機Android、実ニュース本文、実AI精度・実料金、長文・大規模データ、配信先の公開状態反映は未確認。
5. 待機記録の段階間重複を保持したまま、対応関係を分かりやすく束ねる表示と、検索・絞り込み・作業優先度の整備が必要。
6. 生成HTMLは閲覧専用。Python環境を用意せず、単独HTMLだけで安全な承認を完結する機能はない。

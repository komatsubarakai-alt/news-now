# 運営者確認結果のJSON記録（隔離試作）

この機能は、過去の判断と別の確認記録を端末に出力するためのものです。
事件統合・記事除外・進展確定・公開承認・本番反映は実行しません。
元の運営者判断・読み取り専用画面・本番JSON・Actions・予算を変更しません。

## 構成

- `review_form.py`：保存済み評価から対象事件・判断・記事版を固定し、単一HTMLを生成
- `review_form_core.js`：回答、ハッシュ照合、履歴、厳密なJSON検証と競合検出
- `review_form_ui.js`：スマホ向けフォーム、ファイル出力・コピー・明示的取り込み
- `test_review_form.py` / `review_form_tests.cjs`：架空データによる検証
- `review_form_browser.py`：架空データでスマホ表示・貼り付け・ファイル選択・保存確認を検証
- `review-form-demo.html`：架空の4事件・20判断。実際の確認結果を混ぜない

外部JavaScript・CSS・通信・サーバー・新しいAPI呼び出しは不要です。
CSPのconnect-srcはnoneです。Dropboxへの送信、localStorageへの自動保存はありません。
JavaScript無効時は入力・出力・復元できないことを表示します。

```sh
python experiments/engine_v2/review_form.py --demo --output /tmp/review-form-demo.html
python experiments/engine_v2/review_form.py --input /private/assessments.private.json --output /private/review-form.html
```

実データの入力は対象行だけを選択した評価JSONを使用してください。生成コマンドは
リポジトリ内への出力を拒否します。公開サンプルは架空入力を別フォルダーで生成してから
コピーしています。実データ・確認JSON・スクリーンショットをGitへ追加しないでください。

## スマホでの入力・保存・復元

1. 非公開で受け取ったHTMLを端末に保存して開きます。Android実機での挙動は未確認です。
2. 事件単位の4項目を入力します。各判断は開いて個別に入力します。
   事件の回答は個別判断へコピーされません。未入力は未確認のままです。
3. メモを入力し「確認結果をJSONへ書き出す」を押します。
   対応環境では保存先選択、それ以外はブラウザーのダウンロードを使います。
   保存先を選べるかはブラウザー・Android側の設定に依存します。
4. 実際にJSONが保存されたことをファイル管理アプリで確認してください。
   ダウンロード開始を保存完了とは扱いません。保存先を確認した後だけ、
   「JSONを保存したことを確認」を押して再読み込み前の警告を解除できます。
   保存成功を確認できたファイルシステム書き込み経路では警告を解除します。
5. 出力できない場合は、常時表示の「JSONのコピー・読み込み」欄にある「出力JSONをコピー」。
   自動コピー不可ならJSON欄を選択して長押しでコピーし、非公開のテキストファイルへ保存します。
6. 復元時は同じ対象・同じ記事版のHTMLを開き、JSONファイル選択または貼り付け→検証→
   「検証済みの確認結果を取り込む」。検証だけでは入力を変更しません。

読み込み欄は折りたたまず常時表示します。読み込み前の書き出しや保存確認は不要です。
ファイル選択ではAndroidの提供するファイル種類・MIMEにより選択肢が消えないよう、
ファイル種類で絞り込まず内容を検証します。File.text非対応時はFileReaderを使用します。
どちらも使えない場合やcontent:経由の読み取り権限で失敗する場合は貼り付けへ案内します。

保存確認ボタンはJSON生成後（書き出し・コピー）に有効になります。直接保存成功後も
有効のままにし、確認済みと無効状態を混同させません。入力変更・新しい確認結果の取り込み後は
無効化し、理由を表示します。JSONを書き出していない初期状態でも読み込みは可能です。
保存確認は端末保存を運営者が確認したという意味だけで、回答・承認を変更しません。

修正前に同じ架空スナップショットから保存した形式1のJSONも復元できます。
別の対象・記事版のJSONは従来どおり拒否します。保存済みJSONを編集して合わせないでください。

入力はメモリー内です。再読み込み・ブラウザー終了前に必ず出力してください。
Androidの強制終了では離脱警告が出ないことがあります。コピーしただけではファイル保存されません。
単一HTMLのfile: / content:対応、実キーボード、ファイル管理アプリとの連携は実機追加検証が必要です。

## 記録形式1

トップレベル：kind、format_version、dataset_id、records、checksum。
record：format_version、binding、answers、memo、recorded_at、reviewed_at、previous_record_id、record_id。

bindingには事件ID、対象範囲、判断ID（事件単位はnullと対象判断ID一覧）、
判断時の対象事件ハッシュjudgment_hash、現在ハッシュcurrent_hash、元判断全文のハッシュ、
過去・現在・判断元記事のURLと記事版を保持します。

記事版に正式IDがなければderived:付きの保存メタデータ由来IDを使用し、
version_originで区別します。本文ハッシュ・保存記事全文ハッシュも別に保持します。
派生IDを過去に保存された正式版ID、本文取得済み、引用確認済みとは扱いません。

answersの4項目：identity、contradiction、impact、evidence。
選択値は固定集合のみです。メモは1万文字まで。
recorded_atはJSON生成時のUTC時刻です。何も入力していない記録のreviewed_atはnullです。
一部入力がある場合のreviewed_atも出力時刻であり、全項目の確認完了や承認を意味しません。
元判断の日時や引用確認日時を推測で補いません。

## 復元・競合

- 事件・判断・旧／現在ハッシュ・記事版・元判断全文のハッシュが画面と完全一致することを照合
- JSON構造、形式版、重複キー、禁止キー、不正数値、日時、選択肢、記録ID、チェックサムを検証
- 上限5MB・5000記録、深さ40。メモ入力をHTMLとして実行しない
- 記録は前記録IDで連結し、変更時に追記。変更なしの再出力は二重記録を作らない
- 同一JSONの再取り込みは何も増やさない
- 古い履歴の取り込みで新しい結果を上書きしない
- 履歴の分岐・欠落・別事件・別判断・版違い・未出力入力との競合は全体を拒否
- 検証後に入力が変わった場合は再検証が必要。失敗時に途中適用しない
- 任意の時点への自動上書き・競合の自動解決は実装しない。競合ファイルは両方を保管する
- 画面全体の対象スナップショットが変わった場合も旧JSONを拒否。新旧の部分移行は別途設計が必要

SHA-256は破損・対応の照合用であり、電子署名・本人認証ではありません。
JSONを改変してハッシュを再生成できる人を認証する仕組みではありません。

## Dropboxへの手動保存と受け渡し

HTMLや確認JSONをDropboxへ自動送信しません。実データ版の新しいアップロードは別途承認が必要です。
JSONは端末へ保存後、Dropboxアプリのアップロードから、本人専用・共有なしの保存先を選びます。
アップロード完了と保存先を確認し、公開リンクを作成しないでください。
復元にはDropboxからJSONをダウンロードし、元と同じHTMLへ取り込みます。

## 本番接続の阻止条件

認証・権限・暗号化・端末紛失対策、正式な記事版／引用依存、競合解決と取り消し方針、
旧版からの移行、バックアップ・復旧、Android実機の保存／復元検証が必要です。
この確認JSONを既存の運営者判断JSONの代わりに読み込ませないでください。
本番の採用・進展・公開承認の検証ゲートには接続していません。
